# 数字钢卷开卷卷取跟踪算法

## 1. 目标

status 算法监控每台开卷机、卷取机的钢卷号。当某台设备首次出现有效钢卷号，或钢卷号相对上一帧运行态发生变化时：

1. 调用质量接口查询该钢卷的重复生产次数 `prod_no`。
2. 根据设备 `side` 和 `coiler_method` 配置判断开卷或卷取方式。
3. status 算法生成 `StatusResult`，同一帧的变化结果合并到一个 `coiler` 类型 RocketMQ 任务。
4. 消费者执行 coiler 算法，批量转换结果并写入 PostgreSQL 的 `qm_coiler_log`。

coiler 任务在卷号变化并完成 `prod_no` 查询后立即生成，不等待 status 长度采样窗口确认当前运行设备。相同设备的钢卷号未变化时不会重复生成任务。

## 2. 处理流程

```text
MQTT status 点位
      │
      ▼
status 算法更新设备候选运行态
      │
      ├─ 卷号未变化 ────────────────► 不生成任务
      │
      └─ 首次有效卷号或卷号变化
               │
               ▼
         查询钢卷 prod_no
               │
               ▼
       解析开卷/卷取方式配置
               │
               ▼
       返回 List<StatusResult>
               │
               ▼
       use case 发布一条 COILER 任务
               │
               ▼
          coiler 算法消费
               │
               ▼
          qm_coiler_log
```

质量接口查询异常或返回空值时，status 算法仍返回变化结果，生产 use case 仍发布任务，`in_mat_no_prod_no` 写空，避免该钢卷永久漏记。本版本不处理 RocketMQ 重投导致的重复记录。

## 3. 配置说明

### 3.1 方式定义

所有机组的 status 配置都必须在 `tracking` 下配置相同的 `coiler_method_def`：

```json
"coiler_method_def": {
  "uncoiler": {
    "name": ["上开卷", "下开卷"],
    "code": ["11", "91"]
  },
  "coiler": {
    "name": ["上卷取", "下卷取"],
    "code": ["19", "99"]
  }
}
```

- `points[].side=uncoiler` 时使用 `coiler_method_def.uncoiler`。
- `points[].side=coiler` 时使用 `coiler_method_def.coiler`。
- 布尔值为 `false` 时取设备 `coiler_method.false_index` 指定的数组下标。
- 布尔值为 `true` 时取另一个数组下标，即 `1 - false_index`。
- `false_index` 只能配置 `0` 或 `1`；未提供时按 `0` 处理，即 `false→0`、`true→1`。
- `name` 和 `code` 数组都必须恰好包含两个非空元素，且下标必须一一对应。

### 3.2 固定默认方式

当前所有机组、所有设备先统一配置：

```json
"coiler_method": {
  "default": false,
  "false_index": 0
}
```

因此开卷机默认记录为 `11/上开卷`，卷取机默认记录为 `19/上卷取`。

### 3.3 使用点位动态判断

后续某台设备具备方式判断点位时，在该设备的 `coiler_method` 中增加 `name/type`：

```json
"coiler_method": {
  "name": "por1_coiler_method",
  "type": "boolean",
  "default": false,
  "false_index": 0
}
```

处理规则如下：

1. `name` 和 `type` 同时存在时，读取 `point_prefix + name` 对应的当前帧点位值。
2. 点位值支持 boolean、数值 `0/1`、字符串 `true/false/0/1`。
3. 点位值合法时优先使用点位值，不使用 `default`。
4. 点位缺失或无法解析时回退到 `default`。
5. `name/type` 必须同时配置，且 `type` 必须为 `boolean`。
6. `false_index` 表示点位值为 `false` 时使用的定义下标；值为 `true` 时使用另一个下标。

## 4. coiler 任务字段

COILER 任务不再携带单独的 `CoilerEvent`，而是在 `statusContext.results` 中携带同一状态帧产生的 `List<StatusResult>`。`statusContext.candidates/current` 在该任务中为空。

| 任务字段 | 来源 | 数据库字段 |
| --- | --- | --- |
| `unitCode` | status 配置机组编码 | `unit_code` |
| `coilNo` | 发生变化的设备钢卷号 | `in_mat_no` |
| `productNo` | 质量接口返回的重复生产次数 | `in_mat_no_prod_no` |
| `coilerMethod` | side、布尔值和定义数组计算结果 | `coiler_method` |
| `coilerMethodName` | side、布尔值和定义数组计算结果 | `coiler_method_name` |
| `deviceCode` | `points[].code` | `device_code` |
| `deviceName` | `points[].name` | `device_name` |
| `maxLength` | 卷号变化帧的剩余长度 | `max_length` |
| `receivedAt` | 卷号变化帧接收时间 | `create_time` |

`in_mat_no_prod_no` 和 `max_length` 在领域模型中分别使用整数和十进制数，写表时按现有表结构转换为字符串。

## 5. 数据库表

表由数据库脚本预先创建，应用不在启动时自动建表。

```sql
create table public.qm_coiler_log
(
    id                  bigint not null primary key,
    unit_code           varchar(50),
    in_mat_no           varchar(50),
    in_mat_no_prod_no   varchar(50),
    coiler_method       varchar(50),
    coiler_method_name  varchar(50),
    device_code         varchar(50),
    device_name         varchar(50),
    max_length          varchar(50),
    create_user         bigint default '1831666618627928065'::bigint,
    update_user         bigint,
    create_time         timestamp,
    update_time         timestamp,
    create_org          bigint,
    deleted             integer default 0
);

comment on column public.qm_coiler_log.id is '主键';
comment on column public.qm_coiler_log.unit_code is '机组代码';
comment on column public.qm_coiler_log.in_mat_no is '入口物料号';
comment on column public.qm_coiler_log.in_mat_no_prod_no is '入口物料重复生产号';
comment on column public.qm_coiler_log.coiler_method is '开卷卷取方式代码';
comment on column public.qm_coiler_log.coiler_method_name is '开卷卷取方式名称';
comment on column public.qm_coiler_log.device_code is '设备代码';
comment on column public.qm_coiler_log.device_name is '设备名称';
comment on column public.qm_coiler_log.max_length is '最大长度';
comment on column public.qm_coiler_log.create_user is '创建人';
comment on column public.qm_coiler_log.update_user is '更新人';
comment on column public.qm_coiler_log.create_time is '创建时间';
comment on column public.qm_coiler_log.update_time is '更新时间';
comment on column public.qm_coiler_log.create_org is '创建组织';
comment on column public.qm_coiler_log.deleted is '删除标志';
```

## 6. 存储开关

```yaml
tracking:
  storage:
    coiler:
      enabled: true
```

关闭后消费者仍会执行 coiler 算法，但结果仓储不写入 `qm_coiler_log`。
