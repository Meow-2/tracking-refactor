# 钢卷状态跟踪算法

Status 跟踪用于从多台开卷机、卷取机的“钢卷号 + 剩余长度”点位组合中识别当前运行设备。配置示例见 `docs/config/CP1/status.json`。

## 配置

- `tracking.start_condition`：点位值大于等于阈值时启用算法。
- `tracking.sample_count`：同一钢卷参与趋势判断所需的连续消息数，最小为 2。
- `tracking.min_length_change`：窗口首尾最小净变化量，必须大于等于 0。
- `tracking.monotonicity_check_enabled`：是否校验设备方向，默认 `false`；开启后要求开卷机窗口首尾递减、卷取机窗口首尾递增。
- `tracking.points[].code/name`：设备唯一编码和展示名称。
- `tracking.points[].side`：`uncoiler` 表示开卷机，`coiler` 表示卷取机。
- `tracking.points[].coil_no/remaining_length`：设备钢卷号和剩余长度点位。

## 判定与输出

每个设备只保留当前钢卷最近 `sample_count` 个长度值。卷号变化时重新开始采样，并查询新钢卷的重复生产次数 `product_no`；卷号不变时复用已有生产次数，不重复查询。查询失败时 `product_no` 置空且不阻断状态计算。卷号或长度无效时清除该设备窗口。绝对净变化量需达到阈值；开启 `monotonicity_check_enabled` 后，还要求开卷机窗口末值小于首值、卷取机窗口末值大于首值。算法不要求每个相邻采样点都严格单调，中间帧允许抖动。

同一端有多个候选时选择绝对净变化量最大的设备，并列时使用配置顺序。每条消息直接生成开卷端、卷取端两条 `StatusCurrentRuntime` 并保存为 Redis 运行态；开卷卷取方式在新卷首次出现时固化到 candidate，current 从选中的 candidate 复制方式代码和名称。同卷期间方式点位变化不会改写已固化方式。无匹配或产线停机时对应状态 `running=false`，设备、方式、卷号、生产次数和长度为空。

`StatusResult` 不再复制 current。它表示本帧检测到的一次钢卷号变化，字段由变化后的 candidate 和设备配置生成，`running=null` 表示此时尚未经过连续多帧趋势识别。无钢卷号变化时算法返回空列表；同一帧多台设备变化时按配置顺序返回多条结果。状态结果不直接持久化，由生产用例封装成批量 coiler 任务。
