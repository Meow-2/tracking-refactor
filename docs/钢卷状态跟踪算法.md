# 钢卷状态跟踪算法

Status 跟踪用于从多台开卷机、卷取机的“钢卷号 + 剩余长度”点位组合中识别当前运行设备。配置示例见 `docs/config/CP1/status.json`。

## 配置

- `tracking.start_condition`：点位值大于等于阈值时启用算法。
- `tracking.sample_count`：同一钢卷参与趋势判断所需的连续消息数，最小为 2。
- `tracking.min_length_change`：窗口首尾最小净变化量，必须大于等于 0。
- `tracking.current_clear_threshold`：某侧未选中时保留上一 current 的最大计数，最小为 1，缺省时为 1。
- `tracking.monotonicity_check_enabled`：是否校验设备方向，默认 `false`；开启后要求开卷机窗口首尾递减、卷取机窗口首尾递增。
- `tracking.points[].code/name`：设备唯一编码和展示名称。
- `tracking.points[].side`：`uncoiler` 表示开卷机，`coiler` 表示卷取机。
- `tracking.points[].coil_no/remaining_length`：设备钢卷号和剩余长度点位。

## 判定与输出

每个设备只保留当前钢卷最近 `sample_count` 个长度值。卷号变化时重新开始采样，并从 PostgreSQL 的 `qm_dc_repeat_prod_no_log` 获取重复生产次数 `repeat_prod_no`：设备编码以 `por` 开头时，读取该机组该卷的最大次数并插入新记录（首次为 1）；其他设备只查询已分配的最大次数，查不到时按首次生产返回 1，但不插入记录。旧生产记录不会更新。同一帧先完成所有 `por` 设备的分配，再处理其他设备的查询，候选状态与结果仍按配置顺序输出。卷号不变时复用已有生产次数，不重复访问 PostgreSQL。数据库操作失败时 `repeat_prod_no` 置空且不阻断状态计算。卷号或长度无效时清除该设备窗口。绝对净变化量需达到阈值；开启 `monotonicity_check_enabled` 后，还要求开卷机窗口末值小于首值、卷取机窗口末值大于首值。算法不要求每个相邻采样点都严格单调，中间帧允许抖动。

status 运行态仅在重启后恢复 Redis 中接收时间不超过一分钟且与当前配置兼容的快照。旧快照的 `product_no` 可以读取，新快照只写 `repeat_prod_no`。无法恢复时，现场有效卷号按新卷处理，因此 `por` 设备会重新分配次数。PostgreSQL 分配与 Redis 运行态保存不在同一事务中；若前者成功后进程崩溃，重启后可能再次分配。新表建表脚本见 `docs/sql/qm_dc_repeat_prod_no_log.sql`；旧 `qm_dc_product_no` 保留但不再读写。部署新程序前须根据历史跟踪数据填充新表，并校验已有卷的最大次数。

同一端有多个候选时选择绝对净变化量最大的设备，并列时使用配置顺序。每条消息直接生成开卷端、卷取端两条 `StatusCurrentRuntime` 并保存为 Redis 运行态；开卷卷取方式在新卷首次出现时固化到 candidate，current 从选中的 candidate 复制方式代码和名称。同卷期间方式点位变化不会改写已固化方式。候选命中时 current 的 `nullCount` 重置为 1；未命中时计数递增，未超过 `current_clear_threshold` 时保留上一状态，超过阈值后置为 `running=false`、清空业务字段并将 `nullCount` 重置为 1。产线停机、换向或换道时立即清空。阈值为 3 时，计数 2、3 保留，计数 4 清空并重置为 1。

`StatusResult` 不再复制 current。它表示本帧检测到的一次钢卷号变化，字段由变化后的 candidate 和设备配置生成，`running=null` 表示此时尚未经过连续多帧趋势识别。无钢卷号变化时算法返回空列表；同一帧多台设备变化时按配置顺序返回多条结果。状态结果不直接持久化，由生产用例封装成批量 coiler 任务。
